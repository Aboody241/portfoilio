## 1. Professional Identity

### Primary title

# General Software Engineer

**Supporting descriptor:** Software Engineering & Application Development

**Suggested tagline:**

> Building reliable software through thoughtful engineering, practical problem-solving, and continuous learning.

### Positioning statement

The portfolio should present Abdullah as a software engineer with a broad engineering foundation and experience building applications and software products—not as a developer whose professional identity is limited to Flutter.

Flutter remains an important part of his experience, but it is one technology within a broader software engineering skill set.

The portfolio should communicate the ability to:

- Understand a problem and translate it into a software solution.
- Design and implement application features.
- Work with APIs, databases, and backend services.
- Make considered architectural and technical decisions.
- Test, debug, maintain, and improve software.
- Learn and work across different technologies when the problem requires them.

### Important distinction

The professional identity used on the portfolio is not a restriction on job titles. Job applications should use the title that best matches each role and the candidate's demonstrated skills.

Do not position the candidate as a Full-Stack Engineer by default. That title can imply balanced, substantial expertise across frontend and backend, which should only be claimed when supported by experience.

## 6. Recommended Portfolio Technology Stack

The proposed stack for the portfolio website is:

| Layer | Technology | Purpose |
|---|---|---|
| Web framework | Next.js | Build the portfolio website |
| Language | TypeScript | Type safety and maintainable code |
| Styling | Tailwind CSS | Responsive styling and consistent UI implementation |
| Animation | Framer Motion | Purposeful interface transitions and motion |
| Deployment | Vercel | Hosting and deployment workflow |

### Why this stack?

**Next.js**
- Suitable for a content-focused portfolio.
- Supports performant rendering and SEO-friendly pages.
- Provides a structured React-based application framework.

**TypeScript**
- Adds static type checking.
- Helps keep components and content structures maintainable.
- Provides useful experience beyond Dart and Swift.

**Tailwind CSS**
- Supports fast, consistent implementation of the supplied design.
- Makes responsive styling straightforward.
- Avoids unnecessary custom CSS complexity.

**Framer Motion**
- Can provide polished transitions and interaction feedback.
- Should be used selectively, not as decoration on every element.
- Motion must not compromise accessibility or performance.

**Vercel**
- Provides a straightforward deployment workflow for Next.js.
- Supports preview deployments and production hosting.

### Implementation constraints

- Follow the existing design; do not redesign without a clear reason.
- Prioritize responsive behavior on mobile, tablet, and desktop.
- Optimize images and avoid unnecessary large assets.
- Respect accessibility basics: semantic HTML, keyboard navigation, contrast, and reduced-motion preferences.
- Keep dependencies limited to those that provide real value.
- Use reusable components where they improve consistency.
- Keep project content easy to update.
- Add a backend only if a concrete feature requires one.

## 9. Engineering and Presentation Principles

These rules should guide all portfolio decisions:

1. **Engineering first, technology second.** Present the problems solved and the decisions made, not only framework names.
2. **Breadth without exaggeration.** Show multiple areas of experience, but distinguish strong experience from exploration.
3. **Depth through evidence.** A project should demonstrate actual implementation, trade-offs, testing, and problem-solving.
4. **Honest ownership.** State exactly what was personally built and what was collaborative.
5. **No trend-driven claims.** Do not add AI, cloud, DevOps, or other technologies to the skills section without practical evidence.
6. **Keep the site focused.** The portfolio should support job applications, not become an endless side project.
7. **Design fidelity and usability.** Implement the selected design while preserving responsive behavior, accessibility, and performance.
8. **Maintainability.** Keep the website and its content easy to update.
9. **Confidentiality.** Publish only material that is owned by the candidate or explicitly approved for public use.
10. **Continuous improvement.** Update the portfolio as stronger projects and verifiable experience become available.
